# PathBoard テスト仕様書

版：1.0 / 作成日：2026-10-14 / 対象：PathBoard 初期版仕様書1.0

状態：テスト設計。実施済みケースと未実施ケースはimplementation-status.mdに記録する。

## 1. 方針と実行環境

- P0：データ保護・中断復旧・配布成立。失敗はリリース不可。
- P1：主要機能・対応クラウド。初期版公開までに合格必須。
- P2：使い勝手・性能目標。結果と未達理由を記録し、残る制約を明示する。
- 自動：ローカルの単体・統合テスト。安全性を実ファイルと障害注入で検証する。
- 手動：UI、実クラウド、別MacでのPKGとGatekeeper。未実行を合格扱いにしない。

開発Macと別のMacはいずれもApple Silicon / macOS 27.0.1。CPU、RAM、OSビルド、Xcode、同期クライアントの版、ファイルシステム、大文字小文字区別の設定を実行記録へ残す。

CIはmacOSランナーでローカルの自動テストを行う。iCloud、Google Drive、OneDriveはテスト専用領域で手動検証する。個人データや認証情報をPublicリポジトリ、Actions、添付ログへ登録しない。

## 2. テストデータと独立した判定

作業用ルートA/B/C/Dをテスト専用領域に作る。本番Vaultや既存の書類は使わない。クラウドにもサービス別に専用ルートを用意する。事前・事後の一覧とハッシュは転送対象の外へ保存する。

| データ | 内容 |
|---|---|
| D01 | 0バイト、テキスト、日本語Markdown、ランダムバイナリ、画像 |
| D02 | 空フォルダ、深い階層、隠しファイル、`.obsidian`を含む模擬Vault |
| D03 | 同名・別内容、連番済み、拡張子なし、複数ドット、長い名前、空白・絵文字 |
| D04 | 大文字小文字差、Unicode表現差。通常領域と区別可能なテスト領域 |
| D05 | 数GBのファイル、10,000項目・最大10階層の性能用データ |
| D06 | 読取拒否、書込拒否、容量不足を再現できる一時ボリューム |
| D07 | シンボリックリンク、ハードリンク、パッケージ、FIFO等の特殊項目 |
| D08 | Finderタグ、更新日時、POSIXモード、リソースフォークを持つファイル |
| D09 | 各クラウドの取得済み、オンライン専用、オフライン状態の項目 |

データ保護の判定はアプリの成功表示だけに依存しない。別の検査手段で相対パス、項目種別、内容のSHA-256、必要属性を確認する。既存の衝突項目のハッシュを事前に記録し、変更されていないことを確認する。失敗時は元データが残り、少なくとも完全なコピーが存在することを確認する。

障害注入ポイントはコピー中、検証中、確定直前、元再確認、削除直前・直後、履歴保存、復元中。テスト用フックは製品UIへ露出させない。実機強制終了テストも別に実施する。

## 7. クラウドの実機検証

CL-T01〜03は以下の16方向それぞれで実施する。L=ローカル、I=iCloud、G=Google Drive、O=OneDrive。同じサービス内は別の登録フォルダ。各方向でファイル・通常フォルダをコピー／移動し、移動後の取り戻しも行う。

| 元＼先 | L | I | G | O |
|---|---|---|---|---|
| L | L→L | L→I | L→G | L→O |
| I | I→L | I→I | I→G | I→O |
| G | G→L | G→I | G→G | G→O |
| O | O→L | O→I | O→G | O→O |

| ID | 仕様 | 優先/方式 | 手順 | 期待結果 |

| CL-T01 | CL-01/FT-03/04 | P1 手動 | 取得済みD01/D02を各方向へ転送 | 全内容一致、コピー元不変、移動元は検証後だけ消える |

## 10. リリース判定・記録

全P0/P1ケースを合格させる。クラウドのサブケースも個別に記録し、一方向の合格で他方向を合格にしない。未実施のP0/P1はリリースゲート未完了。N/Aは条件と根拠を記録する。

データ欠損、既存データ上書き、誤対象削除、虚偽の完了、中断後の無条件削除、復元での誤削除、PKG起動不能は停止条件。性能未達は測定結果と影響をレビューする。未検証のサービスは対応保証の対象に含めない。
