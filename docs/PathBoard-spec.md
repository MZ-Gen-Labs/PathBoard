# PathBoard 初期版仕様書

版：1.0 / 作成日：2026-10-14

状態：実装用の仕様ベースライン。実装・検証の最新状況はimplementation-status.mdを参照。

本書は会話の決定事項を統合し、未指定の細部を実装側の設計判断として補ったもの。設計判断をユーザーが個別承認したとは扱わない。実装による仕様変更は、本書とテスト仕様書を同時に更新する。

## 1. 決定事項

| 項目 | ユーザー確認済みの内容 |
|---|---|
| 名前 | PathBoard（パスボード） |
| 目的 | 複数の保存先を見渡し、位置を見失わずにファイルを整理する |
| 保存先・配置 | 通常フォルダ・Obsidian Vaultを3〜4個登録、基本は2×2 |
| 操作 | 移動・コピーはパネル間のみ。ドロップ後に移動／コピーを選ぶ |
| 同名項目 | 別名保存／スキップ／キャンセル。上書き・フォルダ統合は初期版の対象外 |
| 組み合わせ | 保存先と配置を名前付きで保存・切り替える |
| Obsidian | ノートリンクを解析・修正しない |
| クラウド | iCloud、Google Drive、OneDrive。その他のクラウドフォルダも対象とする |
| 復元 | 可能な操作を取り戻せる機能を希望 |
| 配布 | GitHub Public、署名なしPKG、自動ビルド。別のMacにPKGでインストール |
| 対象実機 | Apple Silicon、macOS 27.0.1。別のMacも同条件 |
| ライセンス | MIT。著作権表記は公開先GitHubアカウント名 |
| 実装先 | `~/dev/PathBoard/`。空であることを確認済み |

## 2. 実装側で採用する初期版の設計

以下は実装を具体化するための設計判断。特に取り戻しの限界、特殊なファイルの除外、Mac上の検証後に元データを削除する条件は、レビュー時に分かるよう表示する。

- Swift + SwiftUI + AppKitでネイティブアプリを作る。
- 初期版の対応範囲はApple Silicon / macOS 27.0以降。受け入れ検証は27.0.1で行う。過去のOSとIntelは対象外。
- パネルは最大4個。1〜2個でも利用できるが、主要な使用・検証条件は3〜4個。
- 独立したバックアップは作らず、履歴に基づく逆操作で取り戻す。
- 履歴は自動削除しない。履歴だけの手動削除を用意し、取り戻し情報が失われる旨を表示する。
- 転送ジョブは1件ずつ処理する。別ジョブは待ち行列へ入れる。
- 特殊なファイルは最初の実装では明示的に転送対象外とする。対象範囲は5.6に記載。
- パネルの一時拡大は後続版に回す。

## 3. 画面・保存先

### UI-01 保存先登録

フォルダ選択で登録し、表示名を変更できる。保存先を変更・削除してもフォルダの実データは変更しない。利用不可の保存先はパネルを残し、再指定できる。サービス別の固定パスを仮定しない。

同じ保存先を複数パネルへ登録することを許す。パネルが違っても実際の移動先が自分自身になる操作は拒否する。

### UI-02 2×2配置

左上・右上・左下・右下に配置し、左右と上下の境界で分割比率を調整する。空き枠には「保存先を追加」を表示する。各ツリーは独立してスクロールする。初期ウィンドウは1200×800ポイント、最小は900×600ポイントを設計値とする。長いパスは省略し、全文表示とパスのコピーを用意する。

### UI-03 ツリーと現在位置

フォルダを展開した時に必要な階層を読み込む。起動時にルート全体を走査しない。フォルダ名・ファイル名で並べ、フォルダを先に表示する。外部変更を再読み込みでき、更新しても存在する項目の展開・選択状態を維持する。

現在フォルダ、選択項目、ドロップ対象は別の状態として表示する。フォルダ行を選ぶと現在フォルダを更新し、ファイル選択ではそのファイルの親を現在フォルダとする。展開ボタンだけの操作は現在フォルダを変えない。

隠し項目は既定で非表示。表示設定を切り替えられる。非表示項目も同名判定とフォルダ転送には含める。

### UI-04 ドラッグ＆ドロップ

複数選択できる。フォルダ行へのドロップはそのフォルダ、背景へのドロップは現在フォルダが対象。ファイル行へのドロップは拒否する。ドラッグ中に対象パスを表示する。

ドロップ後に対象数、元と先のパス、「移動」「コピー」「キャンセル」を表示する。選択前は転送を開始しない。Escでキャンセルできる。同一パネル内とFinderとの移動・コピーは拒否し、ファイルを変更しない。

### UI-05 処理表示

待機中、準備中、取得待ち、コピー中、検証中、元データ削除中、完了、部分成功、中断、失敗、要確認を表示する。元データ削除に失敗した場合は「コピー済み・元データあり」と明記する。サイズ不明では不確かな進捗率を表示しない。

## 4. ワークスペース

### WS-01 保存・編集

名前、保存先の参照、表示名、パネル位置、分割比率、展開状態、現在フォルダ、スクロール位置、隠し項目表示を保存する。新規保存・名前変更・削除を用意する。既存名への保存は更新を確認し、ワークスペース削除は実ファイルを削除しない。

### WS-02 復元

切り替えと再起動で最後の状態を復元する。消えた現在フォルダは最も近い存在する親へ戻り、理由を表示する。ルートが消えた場合は利用不可とする。設定破損時は元の設定ファイルを残して復旧を案内し、登録先を推測して実ファイルを操作しない。

### WS-03 処理中の切り替え

転送開始時の元・先を固定する。画面やワークスペースを変更しても転送先は変わらない。共通の処理一覧から進捗を確認できる。

## 5. ファイル処理

### FT-01 準備と重複選択

実際の保存先、アクセス権、同名項目、対象種別を確認する。別パネルで同じフォルダを見ている場合も、自分自身への操作、フォルダをその配下へ入れる操作を拒否する。親フォルダと子を同時選択した場合は親だけを処理する。

### FT-02 同名項目

既存項目を一切上書きしない。ファイル同士、フォルダ同士、ファイルとフォルダの組み合わせも同じ衝突扱いとする。大文字小文字やUnicodeの差は実際の保存先ファイルシステムの判定に従う。

別名は最後の拡張子を保ち、`note (1).md`、`note (2).md`の順で空きを探す。拡張子なし・フォルダには末尾に` (1)`を付ける。実行時に同名項目が増えた場合も再判定し、上書きしない。「キャンセル」はジョブの未実行項目を中止し、完了済みの項目を巻き戻さない。

### FT-03 コピーと検証

初期版は同じ保存領域内でもコピー方式に統一する。転送先の親に操作ID付きの一時項目を作成し、その操作の所有する項目だけを管理する。一時項目もクラウドに同期される可能性があるため、完全に不可視とは約束しない。

通常ファイルは全内容を読み、SHA-256を比較する。フォルダは相対パス、項目種別、全ファイルのサイズとSHA-256を比較し、空フォルダも含める。隠し項目を含む。読み取り失敗や必要属性の保存失敗は成功扱いにしない。

コピー後に元データの一覧・内容と必要属性を再確認する。転送中の追加・削除・編集を検出した場合は要確認とし、移動の元データ削除を止める。最終確定は上書きなしで行う。衝突発生時は再選択を求める。コピー完了後も元データを残す。

### FT-04 移動

状態は「記録 → 準備 → コピー → 検証 → 転送先確定 → 元の再確認 → 元をゴミ箱へ保全 → 完了」。元削除の前に履歴を永続化する。元は検証後にゴミ箱へ保全し、完全削除には切り替えない。保全失敗は転送先を残し、コピー済み・元データありとする。

クラウドもMac上で内容を読み取って検証する条件で処理する。サーバーへの同期完了は削除条件に含めず、UIと配布説明で明記する。これはデータの二重バックアップを維持するモードではない。

外部アプリがアクセス調整を尊重しない変更や、最終確認と削除の間の競合を完全に排除できるとは約束しない。検出できる変更は削除を止め、競合検証に合格するまで実データでの移動を有効にしない。

### FT-05 キャンセルと中断復旧

キャンセル受理後は次の項目を開始しない。コピー・検証中は元削除へ進まない。元削除が始まった項目は結果を記録して停止する。一時項目だけを片付け、確定済み項目や既存項目は削除しない。

再起動後は未完了履歴を表示する。無条件に転送・削除を再開しない。元と先を再検証し、結果が曖昧なら要確認のまま残す。ログ・設定への書き込み失敗時は削除工程へ進まない。

### FT-06 対象種別・属性

初期版の対象は通常ファイルと通常フォルダ。パッケージ、シンボリックリンク、ハードリンク、特殊ファイルは転送を拒否し、理由を表示する。フォルダ内部で検出した場合は、そのトップレベル項目全体を元削除せず停止する。リンク先を辿らない。

内容、名前、フォルダ構造、更新日時、基本POSIXモード、ユーザー属性（Finderタグ、リソースフォーク等）を保持する設計とする。初期版では1属性16MiBを超える場合は停止し、履歴には属性本文ではなくハッシュを保存する。クラウド固有の管理属性は再生成をプロバイダーに任せる。所有者・ACL・ファイルシステム固有フラグの完全再現は初期版では保証しない。復元に必須の属性を保存できない場合は元削除を止める。属性の具体的分類と実現可否は技術検証で確定する。

## 6. 取り戻し

### UN-01 履歴

ジョブIDと項目ID、日時、元と先、別名、検証情報、処理段階、結果、復元結果を永続化する。履歴に本文は保存しない。再起動後も履歴から取り戻せる。公開ログには個人のファイル名・絶対パスを載せず、診断出力も既定で伏せる。

### UN-02 移動を戻す

転送先の項目が記録時の内容・必要属性と一致し、利用可能な場合に戻せる。元の場所へコピーし、検証・確定に成功した後に転送先を再確認して削除する。同名があれば別名／スキップ／キャンセルを選ぶ。元の親フォルダが消えた場合は要確認とし、勝手に再作成しない。

別名で戻した場合は「別名で戻しました」と表示し、元と同じ名前に戻ったとは表示しない。

### UN-03 コピーを取り消す

この操作が作ったコピーが未変更であることを検証し、確認後にゴミ箱へ移す。対応しない保存先では処理を止め、完全削除へ切り替えない。別名コピーも実際の確定先を対象とする。

### UN-04 復元不可・部分復元

変更、改名、消失、利用不可、属性差異では自動復元・削除を止める。履歴上で対象の内容・識別情報が一致しない項目を、名前だけで同一と判断しない。項目単位の復元結果を表示し、復元済み項目の二重実行を拒否する。復元自体の中断もFT-05と同様に記録する。

## 7. クラウド

### CL-01 共通対応

インストール済みの同期アプリがMacへ提供するフォルダを操作する。クラウドAPI、ログイン、File Provider拡張の新規開発は行わない。iCloud・Google Drive・OneDriveを重点検証し、未検証のサービスはその旨を明記する。

### CL-02 オンライン専用・通信失敗

未取得の内容は読み取りに必要な取得を待ち、取得待ちを表示する。拒否、オフライン、容量不足、プロバイダー停止では元削除をしない。無期限にUIを止めず、キャンセル可能にする。ツリーを開くだけで全ファイルの本文を取得しない。

### CL-03 完了の意味

表示は「Mac上の処理完了」。サーバーの同期完了を確認できないため「クラウド同期完了」と表示しない。クラウドごみ箱やバージョン履歴による復旧は本アプリの保証に含めない。

## 8. 技術・保存

| 担当 | 方針 |
|---|---|
| 画面全体 | SwiftUI |
| ツリー・ドラッグ | AppKit / NSOutlineView、NSViewRepresentableで組み込み |
| アクセス調整 | Foundation / NSFileCoordinator。プロバイダーと外部変更の検証を行う |
| ファイル権限 | フォルダ選択とbookmarkで参照。初期版はApp Sandboxを使わない設計。OSのプライバシー制御は尊重する |
| 設定・履歴 | Codable + JSON。操作ごとの履歴を原子的に保存し、削除前の記録失敗は処理停止 |
| データ配置 | ユーザーのApplication Support配下。登録Vault・フォルダへ管理ファイルを置かない |
| 内容検証 | CryptoKit / SHA-256。大容量を全てメモリに読み込まない |
| ビルド | Xcode。現在のMacでXcode 27.0を確認済み |
| 自動化 | GitHub ActionsのmacOSランナー。対応SDKとXcodeを固定する |

App Sandbox不使用は選択外のファイルを操作する機能を追加する意味ではない。処理対象は登録ルート配下とアプリが作成した管理データに限定する。設定や履歴の不正なパスを信用して削除しない。

## 9. 配布

### DS-01 CI

PR・通常のpushでビルドと自動テストを実行する。リリース用タグ`v*`でテスト成功後にReleaseビルド、PKG作成、内容検査、SHA-256出力を行い、GitHub Releaseへ添付する。タグ付与前に、そのコミットの手動受け入れ記録とリリース判定をレビューする。自動テストの成功だけでクラウド実機試験を合格扱いにしない。失敗したビルドを公開しない。テスト用個人アカウントやクラウドデータはCIへ持ち込まない。

### DS-02 PKG

arm64のPathBoard.appをpkgbuild/productbuildで`/Applications/PathBoard.app`へインストールする。Developer IDによるPKG署名・アプリ署名、公証は行わない。実行に必要なアドホック署名は証明書なしで扱い、配布説明で区別する。

上書きインストールで設定・履歴を保持する。アプリ内自動更新は対象外。Gatekeeperの無効化や隔離属性の自動削除をインストール処理に入れない。別のMacで、WebからダウンロードしたPKGのインストールと初回起動を検証し、必要な許可操作をREADMEに記載する。

### DS-03 公開情報

リポジトリはPublic。LICENSEに標準MIT条文と`Copyright (c) 2026 <GitHub公開先アカウント名>`を記載し、アプリにも同梱する。外部依存のライセンスを別途確認する。READMEに対応環境、対象外、復元条件、クラウド完了条件、インストール・更新・削除手順を記載する。

## 10. 非機能・受け入れ

### NF-01 性能の目標

受け入れ用データは通常ファイル10,000個、1階層最大1,000項目、最大10階層。ローカルの取得済みデータで、初期パネル表示5秒以内、1,000項目の階層表示2秒以内、転送中のキャンセル表示反応1秒以内を目標値とする。計測Macとデータ構成を記録し、クラウドの取得時間は別に計測する。

### NF-02 判定

テスト仕様書のP0/P1を合格させる。データ欠損、既存データ上書き、誤対象削除、虚偽の完了表示、中断復旧での無条件削除、PKG起動不能はリリース不可。未検証のクラウドを検証済みと表示しない。
